Overview

Money lands in a bank account. The books say what it was for. This connects them — and when one payment covers several entries, it notices instead of guessing.

What happens to one payment

step 1
Narrow
Ledger entries on this account, within a week. Thousands down to a few dozen.
 
→
step 2
Group check
Is one payment settling several invoices? Then a single match would be wrong.
 
→
step 3
Rank
Score what is left on amount, date and account. A trained model, not a rule.
 
→
step 4
Decide
Post it, or hand it to a person. Larger amounts must clear a higher bar.
 

No language model runs in any of those four steps. It is used only to write explanations afterwards, where a wrong word costs nothing and a wrong match costs money.

Trust & evidence

Why these numbers are worth believing, and what they do not say.

✓
Future data never enters training The split is by time and keeps a settlement's records together, so no part of a match can sit on both sides.
✓
The outcome columns are refused Four fields record how a match was resolved. Loading them would be reading the answer; a gate raises before a model reaches disk.
✓
Uncertain matches are never forced Below the bar for its amount, a payment goes to a person with the reason attached.
✓
Two equally good answers are not guessed between When a second combination fits just as well, neither is claimed.
✓
Confidence is a measured frequency Calibrated against how often the answer is actually right, not a transform of a model score. Uncalibrated data is labelled as such.
✓
A model failure cannot post anything Ranker, detector, calibrator and explanation layer were each made to fail on purpose. Every one degrades to review.
✓
Every decision is recorded, and a broken run says so Append-only, enforced by the database. A run that stops halfway is marked failed rather than left looking finished.
